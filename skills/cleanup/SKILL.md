Цель: освободить диск, `/tmp` и деревья, не задев чужого.

Переданные аргументы вызова (подставлены при запуске, пустая строка —
аргументов нет): «$ARGUMENTS».

Допустимые значения: пусто — сухой прогон; `apply` — удаление по
перечню; после `apply` сколько угодно `--exclude '<шаблон>'` — glob
по имени ветви, ручные исключения (например, ветви работающих исполнителей).

Правила раскладки, защищённые ветви и признаки чужого —
`${CLAUDE_PLUGIN_ROOT}/README.md`, раздел «Раскладка». Деревья стенда и
проектные строки уборки приходят из `.duty/cleanup.d/`; деревья из
`cleanup.keep_trees` и проекты compose из `cleanup.docker_keep_projects`
не предлагаются к удалению. Правила стенда проекта — в `.duty/access.md`
или `.duty/worker-context.md`, если они есть.

## Шаги

1. Составить перечень, передав сценарию все `--exclude` из переданных аргументов:

   ```sh
   python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/cleanup-candidates.py" "${CLAUDE_PROJECT_DIR}" [--exclude '<шаблон>']...
   ```

   Готово, если вывод — таблица с колонками «Вид | Сабмодуль | Родитель |
   Что | Размер | Решение | Команда». Одна строка — один объект: для
   ветви «Что» — имя ветви, для worktree и каталога — путь, для
   контейнера — имя. Строки опознаются по этим полям, номеров нет.
   Сценарий сам пропускает ветви, выписанные в любой worktree (в том
   числе с незакоммиченными изменениями), и ветви, подпавшие под
   `--exclude`: в перечне они с решением «оставлено: …». Сценарий только
   читает (и обновляет ссылки `origin/*` через `git fetch --prune`).
2. Без `apply` — итог по перечню, ничего не удалять.
3. С `apply` — по строкам, где «Решение» начинается со слова «удалить»,
   по одной:
   - перед командой перепроверить условие строки: для worktree —
     `git -C <путь> status --porcelain` пуст; для ветви —
     `git -C <сабмодуль> merge-base --is-ancestor <ветвь> origin/<родитель>`
     успешна (`origin/<родитель>` содержит вершину ветви; слитость в HEAD
     сабмодуля здесь не мерило) и ветвь не выписана ни в одной worktree
     (`git -C <сабмодуль> worktree list --porcelain`); для scratchpad —
     нет процесса с текущим каталогом внутри
     (`ls -l /proc/*/cwd 2>/dev/null | grep -F <путь>` пуст); для
     строк вида `results` — каталог прогона не живой
     (`python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/cleanup-candidates.py" --live <каталог results/ верхнего уровня>`
     печатает «не живой»); для проектных строк из `.duty/cleanup.d/` — условие, которое строка называет
     в колонке «Решение» или «Команда»; деревья из `cleanup.keep_trees`
     не трогать;
   - выполнить команду из колонки «Команда» без изменений; для ветви это
     `git branch -D <ветвь>`, и только сразу после проверки выше;
   - проверить результат: путь исчез (`test ! -e <путь>`), ветвь
     исчезла (`git -C <сабмодуль> rev-parse --verify --quiet <ветвь>`
     не находит), `docker image prune` и `docker builder prune` вывели
     освобождённое место («Total reclaimed space»). Кэш сборки удаляется
     только старше двух суток (`--filter until=48h`), свежий не трогать
     и `docker builder prune` без фильтра не запускать.
   Именные ветви разработчиков в origin (имя без префикса) не удаляются
   и в перечень слитых не попадают: «именная, владелец <автор>».
   Строки «оставлено», «решение пользователя» и «сведения» не исполнять.
   Команда `sudo -A -p …` открывает окно ввода пароля; не открылось
   или отказ — строка остаётся «оставлено», обходов нет.
   Команда `rootlesskit rm -rf -- <путь>` (владелец — uid из подчинённого
   диапазона `/etc/subuid`, файлы контейнеров rootless Docker) выполняется
   без root и без окна пароля. Строка «нужен sudo» — настоящий root или
   иной uid, решение пользователя; в `apply` не исполняется.
4. После `apply` — повторить шаг 1. Готово, если каждая строка перечня
   либо удалена и проверена командой, либо оставлена с причиной в итоговой
   таблице; повторный прогон показывает только оставленные строки
   с причинами (строка кэша Docker с нулевым освобождаемым объёмом
   не показывается). Строка кэша сборки после `apply` может остаться:
   её «Размер» — весь освобождаемый кэш по `docker system df`, включая
   свежий моложе двух суток, который не удаляется; это не оставленная
   строка, а сведения о свежем кэше.

## Итог

По `${CLAUDE_PLUGIN_ROOT}/reference/report.md`. Таблица:

| Что | Где | Размер | Удалено / оставлено и почему |

Строки одного вида с одним решением и одним сабмодулем сливаются
в итоговой таблице («36 ветвей репозитория, слитых в родителя — удалены»), в перечне
они остаются отдельными. «Решения за пользователем» — строки «решение
пользователя» с командой, оформленные вопросом с вариантами по форме
`report.md`. «Что не проверено» — что сценарий
не смог измерить.

Запрещено: завершать процессы (`kill`, `pkill`, `killall`, по образцу);
трогать worktree с грязным деревом и чужие незакоммиченные правки;
удалять ветви `git.keep_prefixes`, `git.protected`, `git.working` и именные
ветви разработчиков; команды проекта массового снятия стендов (`forbid.rules`);
действия с root без
`sudo -A -p`; что-либо за пределами перечня.
