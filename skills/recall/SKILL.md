Цель: записка задачи и вопрос пользователю несут ссылки на найденные
разделы документов, а не пересказ по памяти. Навык ничего не правит, кроме
своего файла итога, который пишет `recall.py save`.

Переданные аргументы вызова (подставлены при запуске, пустая строка —
аргументов нет): «$ARGUMENTS».

Допустимые значения: тема словами (одна-две строки). Пусто — итог из одной
строки об этом.

Корень проекта — `${CLAUDE_PROJECT_DIR}`; источники — ключи `docs.decisions`,
`docs.openspec`, `docs.rules`, `docs.recall` конфигурации
(`${CLAUDE_PLUGIN_ROOT}/reference/config.md`), каталог итога —
`paths.results`. Где итог лежит и кто его проверяет — README плагина,
«Ворота постановки».

## Шаги

1. **Ключевые слова.** Из темы взять два-четыре слова: русские и английские
   (имена файлов, идентификаторы, названия требований). Готово: список слов.
2. **Сбор кандидатов.** Одной командой:

   ```sh
   python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/recall.py" "<тема>" \
     --root "${CLAUDE_PROJECT_DIR}" --keyword <слово> [--keyword <слово> …]
   ```

   Вывод — разделы «Записи решений», «Спецификации», «Правила», «Документы»,
   «История git», «Реплики пользователя». Деревья `Grep` и `find` по всему
   проекту не обходить. Готово: вывод получен; пустые разделы названы.
3. **Чтение.** Прочесть найденные записи решений целиком, включая условия
   пересмотра и записи, на которые они ссылаются; нужные разделы
   спецификаций (требование целиком) и документов; реплики и коммиты
   использовать как указатели на документы, а не как источник решения.
   Слова не дали записей — один повтор с другими словами. Готово: по каждой
   найденной записи известно, что выбрано и при каком условии пересматривается.
4. **Итог в файл.** Содержание — разделы «Итог» ниже; записывает его
   сценарий (у агента нет Write и Edit), текст передаётся со stdin:

   ```sh
   python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/recall.py" save "<тема>" \
     --root "${CLAUDE_PROJECT_DIR}" <<'EOF'
   <итог в Markdown>
   EOF
   ```

   Сценарий сам вычисляет имя `<paths.results>/recall/<тема-латиницей>-<ГГГГММДД-ЧЧММ>.md`,
   создаёт каталог и печатает путь; тот же текст вернуть в ответе. Готово:
   сценарий напечатал путь.

## Итог

Таблица `Источник | Файл и раздел | Суть одним предложением | Статус`;
статус — «решено», «открытый вопрос» (с условием пересмотра) или
«упоминание». Затем:

- строка `По теме: решено в <записи, требования> / открытый вопрос <файл> /
  записей нет` (нужное);
- блок для раздела «Ссылки» записки: строка `Справка: <абсолютный путь файла
  итога>` и строка `Прочитанное при постановке: <пути и разделы>`;
- одно предложение для вопроса пользователю в форме `По документам: <что
  найдено или «записей нет»>`.

Затем «Решения за пользователем» и «Что не проверено» по
`${CLAUDE_PLUGIN_ROOT}/reference/report.md`.

Запрещено: правка любых файлов, кроме файла итога (`recall.py save`); запись по теме, найденная
только в репликах или `git log`, без подтверждения в документе, как «решено»;
`git add`, коммиты, push; завершение процессов.
