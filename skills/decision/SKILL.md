Цель: решение пользователя попадает в одну запись `docs/decisions/`
по форме записи 0065, а не в новую запись рядом с прежней.

Переданные аргументы вызова (подставлены при запуске, пустая строка —
аргументов нет): «$ARGUMENTS».

Допустимые значения: есть `::` — слева тема, справа решение (режим
записи). Нет `::` — только тема (режим справки: ничего не записывать).
Пусто — итог из одной строки об этом.

Каталог записей — `${CLAUDE_PROJECT_DIR}/docs/decisions`. Форма записи —
запись `0029-*.md` и образец `0052-*.md` там же; язык — по
`${CLAUDE_PROJECT_DIR}/docs/russian-prose.md`: без калек, без «мы»
и «коллег», термины едины («дефект», «ветвь»).

## Шаги

1. **Поиск по теме.** Из темы взять два-три ключевых слова (в том числе
   английские из имени файла) и выполнить
   `grep -il -e '<слово>' ... "${CLAUDE_PROJECT_DIR}"/docs/decisions/*.md`;
   прочесть найденные записи и строку указателя `README.md`. Готово:
   назван список записей по теме либо «записей нет».
2. **Справка (нет `::`).** Для каждой найденной записи — путь и суть
   в одном предложении (что выбрано, что условием пересмотра). Нет
   записей — «по теме решения нет». Дальше шаги не выполняются.
3. **Запись есть (есть `::`).** Решение пользователя меняет или уточняет
   найденную запись — править её в том же файле: Y-statement, варианты,
   пересмотр; номер, имя файла и строка указателя остаются (строка
   указателя меняется, только если изменилась суть решения). Запись
   только про соседнюю тему, а не про эту, — не править, перейти к
   шагу 4. Сомнение, та ли это запись, — не править и не создавать,
   вернуть пути в «Решения за пользователем».
4. **Новая запись.** Номер:

   ```sh
   bash "${CLAUDE_PLUGIN_ROOT}/scripts/decision-number.sh" "${CLAUDE_PROJECT_DIR}/docs/decisions"
   ```

   Сценарий выдаёт номер атомарно и резервирует файл `NNNN-reserved.md`.
   Имя — `NNNN-тема-латиницей-через-дефис.md`: `mv` резерва в это имя,
   затем записать текст. Не удалось написать запись — удалить резерв.
   Номер самим не вычислять.
5. **Текст.** Заголовок `# NNNN. <суть решения>`; абзац «В условиях …,
   учитывая …, выбрано …, чтобы …, ценой …» на одно-три предложения;
   при необходимости абзац про механику; `Варианты:` — по строке на
   отвергнутый вариант; `Пересмотр:` — одной строкой, условие. Длина
   не больше страницы; без даты, статуса, цитат, хронологии, номеров
   сборок и хешей. Сведения, которых пользователь не называл (условия,
   варианты, цена), не выдумывать: строку, которой нет в решении,
   пропустить, в «Что не проверено» назвать, чего не хватило.
6. **Указатель.** Строка в таблицу `README.md` в порядке номеров:
   `| NNNN | <Тема> | [<Решение одной фразой>](NNNN-имя.md) |`.
7. **Коммит.** Только свои файлы по путям, без `git add -A`, `-u`,
   `stash` и без push:

   ```sh
   git -C "${CLAUDE_PROJECT_DIR}" add docs/decisions/NNNN-имя.md docs/decisions/README.md
   git -C "${CLAUDE_PROJECT_DIR}" commit -m 'docs: запись NNNN — <тема>' -m 'Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>' -- docs/decisions/NNNN-имя.md docs/decisions/README.md
   ```

   Чужие незакоммиченные правки тех же файлов — коммит не делать,
   сообщить. Готово: `git show --stat HEAD` называет только эти файлы.

## Итог

Режим записи — одна строка: `NNNN | путь | хеш коммита` (для правки
существующей записи — слово «правка» вместо нового номера). Режим
справки — таблица `Запись | Суть` по `${CLAUDE_PLUGIN_ROOT}/reference/report.md`.
Затем «Решения за пользователем» и «Что не проверено».

Запрещено: записывать в режиме справки; вычислять номер без сценария;
править записи, не относящиеся к теме; `git add -A`, `git add -u`,
`git stash`; push; `todo.local.md`; завершение процессов.
