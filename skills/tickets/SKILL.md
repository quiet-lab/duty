Навык работает, только если в конфигурации есть раздел `[jira]`; иначе
сценарий печатает одну строку об этом, и навык заканчивается. Группы,
метки, статусы и пороги — раздел `[tickets]`
(`${CLAUDE_PLUGIN_ROOT}/reference/config.md`).

Переданные аргументы вызова (подставлены при запуске, пустая строка —
аргументов нет): «$ARGUMENTS».

Допустимые значения: пусто — выборка по умолчанию (`tickets.jql`);
`all` — все нерешённые тикеты проекта `tickets.project`; иное — фильтр
по группе, ключу или заголовку поверх выборки по умолчанию.

Первое и единственное действие — одна команда, ветвление по аргументу
делает сам сценарий:

```sh
python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py" '$ARGUMENTS'
```

## Шаги

1. Команда выше уже выполнена; повторно не запускать. Готово, если
   вывод — таблица Markdown групп, строка «Для обсуждения: …» и строка
   «Отчёт: <путь>».
   Строка «ОСТАНОВКА: Jira ответил 401/403» — повторять нельзя: итог
   из одной строки об этом и раздел «Что не проверено».
2. Прочитать из файла отчёта только раздел `## Для обсуждения`
   (`sed -n '/^## Для обсуждения/,$p' <путь>`). Больше ничего
   не запрашивать: сценарий уже прочитал Jira.

## Итог

По `${CLAUDE_PLUGIN_ROOT}/reference/report.md`: таблица из вывода
сценария без изменений в ячейках и путь отчёта; «Решения
за пользователем» — пункты раздела «Для обсуждения» отчёта (неясные,
вероятные дубли, застрявшие в проверке) по одному на строку со ссылкой;
«Что не проверено» — недоступная Jira или отсутствие раздела `[jira]`.
Комментариев к таблице не писать.

Запрещено: менять тикеты (только чтение Jira), повторять запросы после
401/403.
