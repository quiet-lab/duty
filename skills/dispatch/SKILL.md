Главная сессия выносит задачу в свой workspace herdr, чтобы её ход,
вопросы и долгие команды не занимали контекст главной сессии. Навык
выполняется в главной сессии, а не форком: записку составляют из того,
что знает только она, — цели, сделанного, решений пользователя. Сам
запуск — сценарий `dispatch.sh`, одна команда с проверкой каждого шага.

## Когда выносить

Задача подпадает под вынос, если выполнено хотя бы одно:

- занимает местный стенд, его экземпляр, домен студии или узел Jenkins;
- содержит прогон, сборку или ожидание дольше 10 минут;
- правит больше одного репозитория (монорепозиторий и сабмодули
  считаются по отдельности);
- идёт через изменение OpenSpec.

Остальное — субагентом главной сессии или навыками `/duty:*`.

## Вход

`$ARGUMENTS` — `<имя-задачи> <модель> [текст задачи или путь к записке]`.

- Имя — `[a-z][a-z0-9_-]{0,31}`, говорящее: оно же имя агента herdr и сессии Claude и имя каталога
  задачи; метка workspace и вкладки — «имя · модель». `list` и `close`
  как имя не годятся.
- Модель — по лесенке из раздела «Модель» ниже.
- Третий аргумент — путь к готовой записке или текст цели.

## Модель

Признаки проверяются до запуска; подходит самая дешёвая ступень, у которой
выполнены все признаки; один признак следующей ступени поднимает задачу
на неё.

- `haiku` — команды уже написаны, решений по ходу нет, итог проверяется
  одной командой: пробы, перечни, запуск готовых сценариев.
- `sonnet` — есть образец или спецификация, по которой делать; один
  репозиторий; готовность проверяется командой (тесты,
  `openspec validate --strict`, линтеры); новых решений о поведении
  не требуется: правка по правилу, документ по готовому решению, прогон
  и разбор вывода, настройка через REST.
- `opus` — хотя бы один признак: причина падения неизвестна и воспроизведения
  нет; проектируется новое поведение, схема данных или протокол; код без
  образца в репозитории; конфликт двух правил или спецификаций; слияние
  с конфликтами; задача затрагивает несколько репозиториев.
- `fable` — только когда это слово стоит в аргументе: главная сессия
  передаёт его после согласия пользователя, предложив Fable с обоснованием.
  Признаки, при которых его предлагать: Opus дважды вернул отчёт с ошибкой
  или противоречием; решение меняет правила проекта или записи решений;
  набор из многих спецификаций или репозиториев, принимаемый вместе; ошибка
  дорога и необратима (выкат, конвейер, перенос в `master`).

Ревью. Исполнитель в «Завершении» проверяет diff задачи навыком
`/code-review <уровень>`: `high` для `opus` и для любого изменения
в `legacy/**`, `medium` для `sonnet`, для `haiku` ревью не выполняется.
Ревью — цикл «ревью, исправление автором, тесты, повторное ревью» не больше
чем в два круга; результат — раздел «Замечания ревью» в `report.md`. Если ревью дважды
подряд находит подтверждённые дефекты правильности у одного исполнителя,
следующая задача такого рода ставится на ступень выше.

Правила движения:

- Вверх — по сигналу из отчёта исполнителя: «не решено», второй провал
  проверки, противоречие отчёта фактам, больше трёх открытых вопросов.
  Задача перезапускается на ступень выше с тем же `brief.md` и `report.md`
  предыдущего исполнителя.
- Вниз — через записку: `brief.md` и критерии приёмки пишет модель
  на ступень выше исполнителя, исполняет дешёвая.

## Шаги

1. Составить записку, если третий аргумент — не путь к готовой: файл
   в scratchpad по `${CLAUDE_PLUGIN_ROOT}/reference/brief-template.md` —
   цель, сделанное (с хешами), где остановились, следующие шаги,
   команды проверки, принятые решения, ссылки. Сведения — ссылками
   на файлы, `tasks.md`, записи решений и тикеты, без пересказа.
   Разрешения на push, pull request, записи во внешних системах —
   явно, иначе их нет.
2. Если для задачи действуют свои запреты и решения сверх общих
   (`${CLAUDE_PLUGIN_ROOT}/reference/worker-rules.md`), — файл с ними
   в scratchpad, по пункту на строку.
3. Запустить:

   ```sh
   bash "${CLAUDE_PLUGIN_ROOT}/scripts/dispatch.sh" <имя> <модель> \
     --brief <записка> [--rules <файл>] [--main <имя главной сессии>]
   ```

   Вместо `--brief` для короткой задачи — `--goal '<текст>'`: записка
   соберётся из шаблона. `--main` — имя главной сессии из `ListAgents`,
   если оно не совпадает с именем её агента herdr. Корень
   монорепозитория — `${CLAUDE_PROJECT_DIR}`, каталог задачи —
   `../ocp-dev-stand/results/<имя>/`.

   Готово, когда сценарий вышел с кодом 0 и напечатал `workspace=`,
   `pane=`, `status=working`, `status=blocked` или `status=idle`
   (приглашение ушло в транскрипт, а первый ход был коротким). Код 1 — причина
   в последней строке; созданный workspace остаётся для осмотра.
   Предупреждение «herdr не подтвердил готовность агента» не отказ: агент занят
   приглашением с первой секунды, сценарий сам закрепил за ним имя.
4. Записку и правила из scratchpad удалить: копии лежат в каталоге
   задачи.

## Дальше

- Новые запреты и решения пользователя по задаче главная сессия
  дописывает в раздел «Переданные» файла `rules.md` задачи; агент
  перечитывает его перед каждым внешним действием.
- Вопросы агент задаёт пользователю сам в своём workspace; главная
  сессия их не пересылает.
- Итог приходит сообщением `SendMessage` (три строки и путь
  к `report.md`) и уведомлением herdr. Агент закрывает свой workspace
  сам, если `rules.md` не велит оставить; иначе — `dispatch.sh close <имя>`
  после проверки отчёта.
- Открытые workspace задач — `dispatch.sh list`.

## Итог

Одна строка: имя, workspace, модель, состояние агента, путь к каталогу
задачи.
