Цель: решение пользователя попадает в одну запись `docs/decisions/`
по форме записи 0063, а не в новую запись рядом с прежней.

Переданные аргументы вызова (подставлены при запуске, пустая строка —
аргументов нет): «$ARGUMENTS».

Допустимые значения: есть `::` — слева необязательный каталог
(`NN-тема`, например `08-agents-and-docs`) и тема, справа решение
(режим записи). Нет `::` — только тема (режим справки: ничего
не записывать). Пусто — итог из одной строки об этом.

Записи — `${CLAUDE_PROJECT_DIR}/docs/decisions/<NN>-<тема>/<NNNN>-<тема>.md`,
нумерация сквозная и повествовательная, порядок и форма — запись
`08-agents-and-docs/0065-*.md` и вводный абзац `docs/decisions/README.md`;
язык — по `${CLAUDE_PROJECT_DIR}/docs/russian-prose.md`: без калек,
без «мы» и «коллег», термины едины («дефект», «ветвь»).

## Шаги

1. **Поиск по теме.** Из темы взять два-три ключевых слова (в том числе
   английские из имени файла) и выполнить
   `grep -ril -e '<слово>' ... "${CLAUDE_PROJECT_DIR}"/docs/decisions/*/`;
   прочесть найденные записи и их строки в указателе `README.md`.
   Готово: назван список записей по теме либо «записей нет».
2. **Справка (нет `::`).** Для каждой найденной записи — путь и суть
   в одном предложении (что выбрано, что условием пересмотра). Нет
   записей — «по теме решения нет». Дальше шаги не выполняются.
3. **Запись есть (есть `::`).** Решение пользователя меняет или уточняет
   найденную запись — править её на месте: Y-statement, варианты,
   пересмотр; номер и имя файла остаются. Запись только про соседнюю
   тему, а не про эту, — не править, перейти к шагу 4. Сомнение, та ли
   это запись, — не править и не создавать, вернуть пути в «Решения
   за пользователем».
4. **Новая запись.** Каталог — из аргумента; без него — тематический
   каталог указателя, к которому относится тема (сомнение — в «Решения
   за пользователем», запись не создавать). Место — последней
   в каталоге либо сразу за записью, продолжением которой решение
   является (`--after <номер>`). Текст (шаг 5) написать во временный
   файл `<scratchpad>/<тема-латиницей-через-дефис>.md` с заголовком
   `# 0000. …`, затем вставить:

   ```sh
   bash "${CLAUDE_PLUGIN_ROOT}/scripts/decision-number.sh" \
     "${CLAUDE_PROJECT_DIR}/docs/decisions/<NN-каталог>" --insert <файл> [--after <номер>]
   ```

   Сценарий вызывает `scripts/renumber-decisions.py insert` монорепозитория:
   запись получает номер и место, последующие сдвигаются, ссылки на них
   переписываются, указатель порождается `--write-index`; в вывод — путь
   записи. Номер самим не вычислять и файлы не переименовывать.
   Готово: путь из вывода существует, `python3 "${CLAUDE_PROJECT_DIR}/scripts/renumber-decisions.py"
   --write-index --check` выходит с кодом 0.
5. **Текст.** Заголовок `# NNNN. <суть решения>`; следующей непустой
   строкой — `Тема: <тема>` (её берёт указатель); абзац «В условиях …,
   учитывая …, выбрано …, чтобы …, ценой …» на одно-три предложения;
   при необходимости абзац про механику; `Варианты:` — по строке на
   отвергнутый вариант; `Пересмотр:` — одной строкой, условие. Длина
   не больше страницы; без даты, статуса, цитат, хронологии, номеров
   сборок и хешей. Сведения, которых пользователь не называл (условия,
   варианты, цена), не выдумывать: строку, которой нет в решении,
   пропустить, в «Что не проверено» назвать, чего не хватило.
6. **Указатель при правке.** После правки существующей записи
   (шаг 3) — `python3 "${CLAUDE_PROJECT_DIR}/scripts/renumber-decisions.py"
   --write-index`: строка указателя меняется, только если изменились
   заголовок или тема.
7. **Коммит.** Только свои файлы по путям: запись, указатель и файлы,
   в которых сценарий переписал ссылки (перечень — `git status --short`
   после вставки); без `git add -A`, `-u`, `stash` и без push:

   ```sh
   git -C "${CLAUDE_PROJECT_DIR}" add <пути>
   git -C "${CLAUDE_PROJECT_DIR}" commit -m 'Запись NNNN: <тема>' -m 'Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>' -- <пути>
   ```

   Чужие незакоммиченные правки тех же файлов — коммит не делать,
   сообщить. Готово: `git show --stat HEAD` называет только эти файлы.

## Итог

Режим записи — одна строка: `NNNN | путь | хеш коммита` (для правки
существующей записи — слово «правка» вместо нового номера; для вставки —
число сдвинутых записей). Режим
справки — таблица `Запись | Суть` по `${CLAUDE_PLUGIN_ROOT}/reference/report.md`.
Затем «Решения за пользователем» и «Что не проверено».

Запрещено: записывать в режиме справки; вычислять номер и переименовывать
записи без сценария;
править записи, не относящиеся к теме; `git add -A`, `git add -u`,
`git stash`; push; `todo.local.md`; завершение процессов.
