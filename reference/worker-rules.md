# Правила задачи {{NAME}}

Агент `duty:worker` перечитывает этот файл перед каждым внешним
действием. Главная сессия дописывает раздел «Переданные» по ходу работы;
запись там отменяет разрешение из `brief.md`.

## Общие запреты монорепозитория

- Правила `CLAUDE.md` монорепозитория, его `.claude/rules/`
  и `~/.claude/CLAUDE.md` действуют целиком.
- `todo.local.md`, навыки `/handoff` и `/sync-parents` — у главной сессии,
  здесь не выполняются. Защищённые ветви `dev`, `dev2`, `master`
  не удаляются, история `origin` не переписывается. Именные ветви
  разработчиков в origin (имя без префикса) не удаляются, даже слитые.
- Главный checkout монорепозитория и сабмодулей не правится: работа —
  в своих worktree и ветвях, названных в `brief.md`.
- `git add` — только по путям; `git add -A`, `git add -u`, `git stash`
  запрещены.
- Push, pull request, слияние, выкат, записи в Jira, Bitbucket,
  Confluence и Jenkins — только если они явно разрешены в `brief.md`
  или ниже; иначе — вопрос (`agents/worker.md`, п. 5).
- Записка не сужает общие правила (`~/.claude/CLAUDE.md`, «Постановка
  задачи»): оснастка, стенд, двойники, учётные данные — часть задачи.
- Документы и записи, перечисленные в `brief.md`, — источник контекста:
  исполнитель обращается к ним и к связанным записям решений по мере
  необходимости, когда записки не хватает для понимания задачи.
  Противоречие между запиской и записанным решением самостоятельно
  не разрешается, а становится вопросом (`agents/worker.md`, п. 5).
- Вопросы — файлом и сигналом (`ask.py` плагина), не
  `AskUserQuestion`; обратимое — по рекомендуемому варианту с пометкой
  в `state.md`, необратимое ждёт ответа (`agents/worker.md`, п. 5).
- Изоляция — данными: свой экземпляр стенда, свои номера, своя ветвь
  (`docs/isolation.md` монорепозитория). Ресурсы реестра занятости
  (`station`, `studio-<домен>`, `dev-stand-<N>`) — через `busy.py`
  плагина; чужие экземпляры стенда, узлы и домены студии не трогать.
- Независимые подзадачи (субагенты, прогоны, проверки по разным
  репозиториям) выполняются параллельно, если они не пересекаются по
  файлам, ветвям и ресурсам и не мешают другим идущим задачам; перед
  запуском загрузка за минуту ниже числа ядер, доступной памяти не меньше
  четверти. Зависимые или пересекающиеся подзадачи идут последовательно.
- Процессы — останавливать только свои по известным PID; `pkill`,
  `killall`, завершение по образцу запрещены.
- Таймеры, `sleep` и опрос запрещены; ожидание — по событию
  (файл `done` вкладки, `herdr pane wait-output`, `kill -0`); условие другой
  задачи — `signals.py wait <имя>` плагина.
- Ожидание — внутри хода (`wait-done.sh --timeout-s 590`, `herdr pane
  wait-output`); `Monitor` и `run_in_background` для ожидания не используются,
  у субагентов их отвергает хук (`agents/worker.md`, п. 3 и 4).
- Вкладка команды `tab-run.sh` закрывается сама по `done`; вкладки вне
  `tab-run.sh` исполнитель закрывает после снятия ожидания (`agents/worker.md`, п. 4).
- Права root — `sudo -A -p '<зачем, по-русски>' команда`.
- `/tmp` — общий tmpfs: выводы и копии деревьев — в каталог задачи.
- Ревью — по правилу монорепозитория `.claude/rules/code-review.md`;
  уровень и раздел отчёта — `agents/worker.md`, «Завершение», п. 1;
  Fable — только по прямому указанию пользователя, записанному
  в разделе «Переданные».
- До отчёта ветвь доводится местно до конца, включая сравнение снимков
  экрана до и после для изменений вида (стили, классы, разметка,
  атрибуты, к которым привязаны стили): снимки и перечень несовпадений —
  в каталог задачи (`screenshots/`), допустимость решает пользователь
  по вопросу `ask.py`. Pull request — только по решению пользователя
  или главной сессии и только после всех местных шагов.
- Fable субагентом не запускается; модель субагента называется явно. Модель подзадачи — по лесенке признаков в `skills/dispatch/SKILL.md`, раздел «Модель»; выбор и признак — в отчёте, доля субагентов по моделям — строкой отчёта.
