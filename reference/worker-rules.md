# Правила задачи {{NAME}}

Агент `duty:worker` перечитывает этот файл перед каждым внешним
действием. Главная сессия дописывает раздел «Переданные» по ходу работы;
запись там отменяет разрешение из `brief.md`.

Запреты этого раздела принадлежат плагину; остальное названо ссылкой
на файл-владелец. `<плагин>` — каталог плагина из служебного блока
`brief.md`. Правила пользователя (`~/.config/duty/worker-rules.md`) и
проекта (`.duty/worker-rules.md`) — разделы ниже, файлы правил проекта —
`docs.rules` конфигурации; ключи конфигурации — `<плагин>/reference/config.md`.

## Общие запреты плагина

- Правила проекта (`docs.rules`) и `~/.claude/CLAUDE.md` действуют целиком;
  записка не сужает общие правила, чтение документов исполнителем
  и противоречие записанному — `~/.claude/CLAUDE.md`, «Постановка задачи».
- Главный checkout проекта и его сабмодулей не правится: работа — в своих
  worktree и ветвях, названных в `brief.md`. Проектные навыки передачи
  работы и синхронизации веток (`/handoff`, `/sync-parents` и подобные)
  выполняет главная сессия, не исполнитель.
- Защищённые и именные ветви — `git.protected`, `git.working`,
  `git.named_dev_branches`; признак именной ветви —
  `<плагин>/README.md`, «Раскладка». Push с `--force` и в ветви
  `git.protected` запрещён.
- Индекс и `git stash`: `git add -A`, `git add -u` (`git.forbid_add_all`)
  и `git stash` (`git.forbid_stash`) отвергает хук forbid
  (`<плагин>/hooks/forbid.py`); в индекс идут только свои файлы по путям.
- Push ветвей задачи как копий и pull request — `~/.claude/CLAUDE.md`,
  «Ветви, pull request'ы и конвейер»: push разрешён, пока его не запретят
  «Переданные», pull request записка не разрешает.
- Запуск на внешней системе сборки (раздел `[jenkins]`) — тот же раздел
  `~/.claude/CLAUDE.md`: долгое задача не запускает; работа с узлом и
  короткие прогоны — по разрешению записки.
- Слияние, выкат, записи во внешние системы (`[bitbucket]`, `[jenkins]`,
  `[jira]`, документационные сервисы) — только если они явно разрешены
  в `brief.md` или ниже; иначе — вопрос (`<плагин>/agents/worker.md`,
  п. 5). Исключение — тикет по правилу ревью (`docs.review`).
- Вопросы и условие остановки — `<плагин>/agents/worker.md`, п. 5.
- Падения тестов — `~/.claude/CLAUDE.md`, «Починка падающего набора тестов»;
  доводка оснастки — там же, «Оснастка тестов».
- Изоляция — правила проекта (`docs.rules`); ресурсы реестра занятости
  (`busy.resources`) — `<плагин>/README.md`, «Реестр занятости», порядок —
  `<плагин>/agents/worker.md`, п. 6. Чужие экземпляры стендов, узлы
  и общие ресурсы не трогать.
- Параллельность — `~/.claude/CLAUDE.md`, «Постановка задачи»; нагрузка
  и завершение процессов — там же, «Субагенты». Процессы по образцу
  (`pkill`, `killall`, `kill $(pgrep …)`) не завершаются.
- Таймеры и опрос — `~/.claude/CLAUDE.md`, «Устройство кода». Ожидание —
  по событию: файл `done` вкладки, `herdr pane wait-output`, inotify;
  условие другой задачи — `<плагин>/agents/worker.md`, п. 7.
- Ожидание внутри хода, вкладки команд и показ хода ожидания
  (`wait-done.sh --follow`, `wait-remote.sh`) — `<плагин>/agents/worker.md`,
  п. 3 и 4; вкладка открывается только через `scripts/tab-run.sh`
  (`herdr tab create`, `pane run`, `pane send` напрямую отвергает хук
  forbid). `Monitor` и `run_in_background` для ожидания не используются.
- Секреты: пароль литералом в `curl -u` и `sshpass -p`, вывод содержимого
  файлов из каталогов `secrets.dirs` и печать окружения или секретных
  переменных запрещены; файлы доступа читаются в переменные (`set -a; . f;
  set +a`, `python3 -I` без печати) и правятся на месте без вывода
  значений (проверяет хук forbid, `<плагин>/hooks/forbid.py`). Сеть
  станции не переключается, если `forbid.network` включён.
- Права root — `~/.claude/CLAUDE.md`, «Повышение привилегий».
- `/tmp` — общий tmpfs: выводы и копии деревьев — в каталог задачи.
- Ревью и модель на ревью — правило проекта (`docs.review`); прямое указание
  пользователя записывается в «Переданные». Раздел отчёта —
  `<плагин>/reference/report.md`, п. 4.
- Сравнение снимков экрана — `~/.claude/CLAUDE.md`, «Ветви, pull request'ы
  и конвейер»: снимки и перечень несовпадений — в `screenshots/` каталога
  задачи, допустимость решает пользователь по вопросу `ask.py`.
- Модели субагентов — `~/.claude/CLAUDE.md`, «Субагенты»; лесенка —
  `<плагин>/skills/dispatch/SKILL.md`, «Модель»; форма в отчёте —
  `<плагин>/reference/report.md`, п. 3.
