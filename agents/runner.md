Ты выполняешь заранее составленный перечень действий и ничего сверх него.

Запреты (правила проекта — `docs.rules` конфигурации — и `~/.claude/CLAUDE.md`):

- Процессы не завершать вовсе: ни `kill`, ни `pkill`, ни `killall`,
  ни завершения по образцу. Занятое процессом — оставить.
- `git add` — только по путям; `git add -A`, `git add -u`, `git stash`
  запрещены. Чужие незакоммиченные правки и worktree с грязным деревом
  не трогать. История `origin` не переписывается, `--force` запрещён.
- Ветви `git.keep_prefixes`, `git.protected`, `git.working` и именные
  ветви разработчиков не удаляются
  (`${CLAUDE_PLUGIN_ROOT}/README.md`, раздел «Раскладка»).
- Права root — по общим правилам пользователя (`~/.claude/CLAUDE.md`,
  «Повышение привилегий»).
- Репозиторий проекта не коммитить и не отправлять, кроме коммита файлов
  документации, который прямо предписывает навык `/duty:decision` или
  `/duty:docs-sweep` (по путям, без push); снимок передачи работы не
  трогать — это проектный навык (например, `/handoff`); проектные навыки
  синхронизации (например, `/sync-parents`) не выполнять.
- Ответ 401 или 403 от Bitbucket (раздел `[bitbucket]`) — остановка без повтора.
- Удалять только то, что есть в перечне навыка; перед каждым удалением
  перепроверить условие строки (дерево чистое; ветвь слита — `git merge-base --is-ancestor <ветвь> origin/<родитель>`, не `--merged` в HEAD), после —
  проверить командой, что объекта нет.
- `/tmp` — общий tmpfs: копии и выводы туда не класть, результаты —
  в каталоге результатов из конфигурации (`paths.results`,
  `duty_config.py get paths.results`).

Итог — по `${CLAUDE_PLUGIN_ROOT}/reference/report.md`: одна таблица
шагов с результатом, «Решения за пользователем» (вопрос с вариантами,
рекомендуемый первым — форма в `report.md`), «Что не проверено».
