Цель: одна таблица ветвей в `origin` с предложением по каждой, чтобы
пользователь отметил решения в таблице, а не отвечал на вопросы по одной
ветви. Только чтение, `fetch` не выполняется.

Переданные аргументы вызова (подставлены при запуске, пустая строка —
аргументов нет): «$ARGUMENTS».

Допустимые значения: `all` (по умолчанию) или подстрока пути репозитория
(`legacy/tests`, `queue-manager-ui`); `--mine` оставляет только ветви
пользователя.

## Шаги

1. Выполнить одну команду, передав переданные аргументы как есть:

   ```sh
   python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/branches.py" $ARGUMENTS --root "${CLAUDE_PROJECT_DIR}"
   ```

   Готово, если вывод — таблица Markdown, строка «Итого: …» и строка
   «Последний fetch: …». Строка «ОСТАНОВКА: Bitbucket ответил 401/403» —
   повторять нельзя: таблица остаётся без колонки PR, об этом — в разделе
   «Что не проверено».
2. Больше ничего не запрашивать: сценарий уже прочитал `refs/remotes`,
   `git worktree list` и pull request'ы со статусами сборок.

## Итог

По `${CLAUDE_PLUGIN_ROOT}/reference/report.md`: таблица из вывода
сценария без изменений в ячейках. Предложения: «слить» — есть коммиты
впереди и зелёный pull request; «удалить» — ветвь слита в родителя или
pull request слит с той же вершиной; «оставить» — есть незалитое и нет
pull request'а либо сохранённая копия (`backup/*`, `saved/*`); «решить» —
неясно, причина в ячейке (чужая ветвь, красные или отсутствующие сборки,
коммиты после слияния). «Решения за пользователем» — строки «слить»
и «удалить» (слияние и удаление в origin выполняет не навык; удаление —
`/duty:after-merge`) и все «решить». «Что не проверено» — строки
«Не проверено: …» и дата последнего `fetch`, если она старше суток.

Именная ветвь разработчика в origin (имя без префикса: `sergey`, `egor`)
не предлагается к удалению и в слитые не попадает: «оставить: именная,
владелец <автор>»; ветвь, названную именем самого пользователя, решает он.

Запрещено: `fetch`, удалять и сливать ветви, запускать задания Jenkins,
комментировать pull request'ы, повторять запросы после 401/403.
