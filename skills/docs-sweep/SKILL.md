Цель: применить одно правило ко всем документам, где оно действует,
и не испортить код, пути, ссылки и идентификаторы.

Переданные аргументы вызова (подставлены при запуске, пустая строка —
аргументов нет): «$ARGUMENTS».

Допустимые значения: правило (замена «A на B» либо описание вроде
«убрать даты поручений»), необязательные `--paths <маски через запятую>`
и `--dry`. С `--dry` правилом может быть и просто слово или образец поиска
(«заказчик»): это образец, замены нет. Правило не разбирается в точный
образец поиска — итог из одной строки с просьбой уточнить.

Корень — `${CLAUDE_PROJECT_DIR}`. Область, исключения, линтер и правила
языка берутся из ключей `[docs]` (`sweep_area`, `sweep_exclude`, `lint`,
`prose`, `review`, `post_change`).

## Шаги

1. **Область.** Без `--paths`: маски `docs.sweep_area` (нет ключа — `docs/` и
   `*.md` в корне), кроме сабмодулей. Сабмодули входят только когда
   `--paths` называет их путь. Не входят: `.git`, `node_modules` и маски
   `docs.sweep_exclude` (архив изменений спецификаций, указатель записей,
   который правится лишь вместе с записью). Готово: область названа списком масок.
2. **Перечень.** `grep -rnI -e '<образец>' <область>`; для правила без
   образца сперва составить образец и показать его в итоге. Вывод —
   файл, строка, фрагмент. Готово: число файлов и мест названо.
3. **С `--dry` — остановка** с итогом по перечню, ничего не менять.
4. **Критерии пропуска.** Правило не применяется внутри кода (блоки
   с тремя обратными кавычками и `код` в одинарных), путей и имён файлов,
   ссылок (адрес в скобках), идентификаторов и ключей конфигурации,
   цитат кода и названий тикетов, имён ветвей и записей, кроме случая,
   когда правило прямо о них. Каждый пропуск перечислить в итоге с
   причиной.
5. **Замена.** `sed -i` либо `python3 -I` по точному списку файлов из
   перечня; не по всему дереву. Падежи и согласование («заказчика» →
   «проекта») править осмысленно, не механически; сомнительное место
   не менять, а вынести в «Решения за пользователем».
6. **Вычитка.** Для каждого изменённого места прочесть контекст
   (`git diff -U2`) и проверить: фраза грамотна, смысл сохранён, код и
   ссылки целы, и ответить на вопрос ревью документов — повторяет ли
   изменённое место правило, записанное в другом файле
   (правило ревью документов проекта, `docs.review`); повтор заменить
   ссылкой на файл-владелец. Неудачную замену вернуть. Если задан
   `docs.lint`, прогнать эту команду по изменённым файлам (ключ `--paths
   <файлы>`, если команда его поддерживает). Готово:
   каждое место отмечено «верно», «ссылка» или «возвращено», линтер без
   новых находок.
7. **Коммит — по репозиториям отдельно.** Репозиторий проекта: только
   изменённые файлы по путям, `git add <путь>`, коммит по-русски
   с `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Сабмодуль
   правится, только если `--paths` его назвал, и коммитится в самом
   сабмодуле (`git -C <сабмодуль> add <путь>`), в текущей ветви, без
   push; указатель сабмодуля в репозитории проекта не коммитить — назвать
   в «Решения за пользователем». Чужие незакоммиченные правки в тех же
   файлах — файл не коммитить, сообщить. Push не делать.
8. **Особые случаи.** Задет путь из `docs.post_change` — в итоге привести
   его `note` (например, команду обновления зеркала документов); самому не
   запускать. Параллельные правки документов разделяются ветвями и путями, а не замком:
   чужие незакоммиченные правки — по шагу 7.

## Итог

По `${CLAUDE_PLUGIN_ROOT}/reference/report.md`. Таблица:

| Файл | Мест | Было → стало (пример) | Вычитка | Коммит |

Для `--dry` — `Файл | Мест | Пример`. Под таблицей: `git diff --stat`
(со `--dry` — «правок нет»), пропуски с причинами, напоминание из `docs.post_change`, если задет его путь.
Затем «Решения за пользователем» и «Что не проверено».

Запрещено: `git add -A`, `git add -u`, `git stash`; push; правка вне
перечня и вне области; маски `docs.sweep_exclude`; снимок передачи работы проекта; завершение процессов.
