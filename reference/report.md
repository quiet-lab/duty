# Форма итога

Итог навыка — то, что основная сессия читает вместо сырого вывода,
поэтому он короткий и проверяемый.

1. **Одна таблица.** Колонки задаёт навык. Строка — один факт или один шаг
   с результатом; в ячейке — значение, а не пересказ. Ссылки на pull
   request'ы и сборки — Markdown-ссылками. Пустые строки и строки
   «всё в порядке» не добавляются. В итоге исполнителя `duty:worker`
   две таблицы: шаги (ветви, хеши, ссылки) и местные проверки
   (`~/.claude/CLAUDE.md`, «Ветви, pull request'ы и конвейер»); проверки
   набора, если полный прогон идёт в наборе, — отметка об этом.
2. **Решения за пользователем** — перечень того, что навык не вправе
   решить сам: удаление вне правил, слияние, конфликт, неясный владелец;
   в итоге исполнителя — открытые вопросы и шаги, сделанные по рекомендуемому
   варианту.
   Пункт — вопрос с двумя-четырьмя взаимоисключающими вариантами ответа;
   у каждого варианта краткое следствие; рекомендуемый вариант идёт первым
   с пометкой «(рекомендуется)». Форма вариантов — как в `--option`
   `scripts/ask.py` («вариант — следствие»). Под вариантами — строка:
   что, почему нельзя самому, какая команда выполнит. Главная сессия
   переносит пункт в `AskUserQuestion` как есть, не домысливая варианты.
   Нет пунктов — «Нет.». Пример:

   ```text
   Слить ветвь `feature-x` в `main`?
   1. Слить (рекомендуется) — ворота зелёные, затем уборка через `/duty:after-merge`.
   2. Подождать — ветвь остаётся, повторная проверка после новых коммитов.
   Слияние решает пользователь; выполнит `git merge --no-ff <ветвь>` в главном дереве.
   ```
3. **Модель** — под таблицей одна строка: модель исполнителя и признак
   лесенки из `skills/dispatch/SKILL.md`, по которому она выбрана. В итоге
   исполнителя `duty:worker` под ней — строка «Доля субагентов
   по моделям: <модель> N, … (из K)» по счётчику в `state.md`;
   без субагентов — «Доля субагентов по моделям: субагентов нет».
4. **Замечания ревью** — только в итоге исполнителя `duty:worker`, после
   «Модели». Порядок и файл статистики — правило ревью проекта
   (`docs.review`); здесь — форма раздела одной строкой: уровень
   `/code-review`, находок всего, воспроизведено ломающих, исправлено,
   ссылка на тикет с неисправленным (или «тикета нет»). Для `haiku` —
   «не выполнялось».
5. **Что не проверено** — что навык не смог узнать и почему (ответ 401,
   недоступный узел, обрезанный вывод). Нет — «Нет.».

Без вступления, без пересказа шагов, без повторения таблицы словами.
Текст — по-русски; идентификаторы, команды и имена ветвей — как есть.
Значения токенов и паролей в итог не попадают.
