# Правила задачи {{NAME}}

Агент `duty:worker` перечитывает этот файл перед каждым внешним
действием. Раздел «Переданные» дописывают по ходу работы главная сессия
и агент — только ответы пользователя
(`<плагин>/agents/worker.md`, п. 5); запись там отменяет разрешение
из `brief.md`.

Запреты этого раздела принадлежат плагину: он сам проверяет их хуком
или владеет описанным порядком. `<плагин>` — каталог плагина из
служебного блока `brief.md`; ключи конфигурации —
`<плагин>/reference/config.md`. Правила пользователя
(`~/.config/duty/worker-rules.md`) и проекта (`.duty/worker-rules.md`)
подставлены в разделы ниже и действуют наравне с запретами плагина.

## Общие запреты плагина

- Файлы правил проекта (`docs.rules`) действуют целиком; записка
  не сужает общие правила.
- Главный checkout проекта и его сабмодулей не правится: работа — в своих
  worktree и ветвях, названных в `brief.md`.
- Защищённые и именные ветви — `git.protected`, `git.working`,
  `git.named_dev_branches`; признак именной ветви —
  `<плагин>/README.md`, «Раскладка». Push с `--force` и в ветви
  `git.protected` отвергает хук forbid (`<плагин>/hooks/forbid.py`).
- Индекс и `git stash`: `git add -A`, `git add -u` (`git.forbid_add_all`)
  и `git stash` (`git.forbid_stash`) отвергает хук forbid; в индекс идут
  только свои файлы по путям.
- Push ветвей задачи как копий разрешён, пока его не запретят
  «Переданные»; pull request записка не разрешает.
- Слияние, выкат, запуск долгого на внешней системе сборки и записи
  во внешние системы (`[bitbucket]`, `[jenkins]`, `[jira]`,
  документационные сервисы) — только если они явно разрешены в `brief.md`
  или ниже; иначе — вопрос (`<плагин>/agents/worker.md`, п. 5).
  Исключение — тикет по правилу ревью (`docs.review`).
- Вопросы и условие остановки — `<плагин>/agents/worker.md`, п. 5.
- Ресурсы реестра занятости (`busy.resources`) —
  `<плагин>/README.md`, «Реестр занятости», порядок —
  `<плагин>/agents/worker.md`, п. 6. Чужие экземпляры стендов, узлы
  и общие ресурсы не трогать.
- Процессы по образцу (`pkill`, `killall`, `kill $(pgrep …)`)
  не завершаются.
- Ожидание — по событию: файл `done` вкладки,
  inotify; условие другой задачи — `<плагин>/agents/worker.md`, п. 7.
- Ожидание внутри хода, вкладки команд и показ хода ожидания
  (`wait-done.sh --follow`, `wait-remote.sh`) — `<плагин>/agents/worker.md`,
  п. 3 и 4; вкладка открывается только через `scripts/tab-run.sh`
  (`herdr tab create`, `pane run`, `pane send` напрямую отвергает хук
  forbid). `Monitor` и `run_in_background` для ожидания не используются.
- Секреты: пароль литералом в `curl -u` и `sshpass -p`, вывод содержимого
  файлов из каталогов `secrets.dirs` и печать окружения или секретных
  переменных запрещены; файлы доступа читаются в переменные (`set -a; . f;
  set +a`, `python3 -I` без печати) и правятся на месте без вывода
  значений. Сеть станции не переключается, если `forbid.network` включён.
- Команды, запрещённые правилами `[[forbid.rules]]` конфигурации проекта,
  не выполняются.
- `/tmp` — общий tmpfs: выводы и копии деревьев — в каталог задачи.
- Ревью и модель на ревью — правило проекта (`docs.review`); прямое указание
  пользователя записывается в «Переданные». Раздел отчёта —
  `<плагин>/reference/report.md`, п. 4.
- Модели субагентов: лесенка — `<плагин>/skills/dispatch/SKILL.md`,
  «Модель»; форма в отчёте — `<плагин>/reference/report.md`, п. 3.
