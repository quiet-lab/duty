# Форма итога

Итог навыка — то, что основная сессия читает вместо сырого вывода,
поэтому он короткий и проверяемый.

1. **Одна таблица.** Колонки задаёт навык. Строка — один факт или один шаг
   с результатом; в ячейке — значение, а не пересказ. Ссылки на pull
   request'ы и сборки — Markdown-ссылками. Пустые строки и строки
   «всё в порядке» не добавляются.
2. **Решения за пользователем** — перечень того, что навык не вправе
   решить сам: удаление вне правил, слияние, конфликт, неясный владелец.
   По пункту на строку: что, почему нельзя самому, какая команда
   выполнит. Нет — «Нет.».
3. **Модель** — под таблицей одна строка: модель исполнителя и признак
   лесенки из `skills/dispatch/SKILL.md`, по которому она выбрана. В итоге
   исполнителя `duty:worker` под ней — строка «Доля субагентов
   по моделям: sonnet N, opus M (из K)» по счётчику в `state.md`;
   без субагентов — «Доля субагентов по моделям: субагентов нет».
4. **Замечания ревью** — только в итоге исполнителя `duty:worker`, после
   «Модели». Порядок ревью — `.claude/rules/code-review.md`
   монорепозитория; здесь — форма раздела одной строкой: уровень
   `/code-review`, находок всего, воспроизведено ломающих, исправлено,
   ссылка на тикет RP с неисправленным (или «тикета нет»), и та же
   строка, дописанная в `~/.claude/stats/review-rounds.tsv`. Для `haiku` —
   «не выполнялось».
5. **Что не проверено** — что навык не смог узнать и почему (ответ 401,
   недоступный узел, обрезанный вывод). Нет — «Нет.».

Без вступления, без пересказа шагов, без повторения таблицы словами.
Текст — по-русски; идентификаторы, команды и имена ветвей — как есть.
Значения токенов и паролей в итог не попадают.
