Цель: после слияния одного pull request'а привести в порядок ветви,
тикет и задачи изменений спецификаций, не трогая чужого.

Навык работает, только если в конфигурации есть раздел `[bitbucket]`
(тикет — ещё `[jira]`, задачи спецификаций — `docs.openspec`); без раздела
`[bitbucket]` итог — одна строка об этом.

Переданные аргументы вызова (подставлены при запуске, пустая строка —
аргументов нет): «$ARGUMENTS».

Допустимые значения: `<путь сабмодуля или слаг>#<номер>` (например
`services/api#2536`, `tests#647`) или ссылка
`<bitbucket.url>/projects/<КЛЮЧ>/repos/<слаг>/pull-requests/<номер>`.
Пусто или не разбирается — итог из одной строки об этом.

Токены и адреса — из разделов `[bitbucket]` и `[jira]` конфигурации
(`python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/duty_config.py" get bitbucket.url`), доступы и готовые команды проекта —
`.duty/access.md`, если есть; защищённые ветви —
`${CLAUDE_PLUGIN_ROOT}/README.md`, раздел «Раскладка».
Корень проекта — `${CLAUDE_PROJECT_DIR}`.

## Шаги

1. **Найти pull request.** Ключ проекта и слаг — из адреса `origin`
   репозитория (`git remote get-url origin`) или из ссылки аргумента. `GET …/pull-requests/<номер>`:
   нужны `state`, `fromRef.displayId` (ветвь), `toRef.displayId`,
   `title`, `links.self[0].href`. Готово, если `state` = `MERGED`;
   иначе остановка: «pull request не слит (state)», остальные шаги
   не выполняются.
2. **Ветвь в origin.** Защищённая или чужая (README плагина, «Раскладка») — не трогать,
   в «Решения за пользователем». Иначе:
   `git -C <сабмодуль> push origin --delete <ветвь>`. Готово:
   `git -C <сабмодуль> ls-remote --heads origin <ветвь>` пуст. Ветвь
   уже удалена — отметить «уже удалена».
3. **Тикет.** Ключ тикета по образцу `jira.ticket` — из имени ветви, иначе
   из заголовка. Нет раздела `[jira]` — шаг пропускается с пометкой.
   Нет — шаг пропускается с пометкой. Если тикет ведут ещё ветви
   с открытыми pull request'ами (`GET /rest/api/1.0/dashboard/pull-requests?state=OPEN&role=AUTHOR`,
   ветви с тем же ключом тикета) — тикет не переводить, перечислить их
   в «Решения за пользователем». Иначе: `GET …/transitions`, выбрать
   переход с `to.statusCategory.key` = `done`; нет такого перехода —
   в «Решения за пользователем» со списком переходов. Комментарий
   со ссылкой на pull request (`201`), затем переход (`204`). Готово:
   `GET /rest/api/2/issue/<ключ>?fields=status` даёт статус
   категории `done`.
4. **Спецификации.** Для каждого корня из `docs.openspec` (нет ключа —
   шаг пропускается) найти задачи, где упомянуты тикет или ветвь:

   ```sh
   grep -n -e '<ключ тикета>' -e '<ветвь>' \
     "${CLAUDE_PROJECT_DIR}"/<корень docs.openspec>/changes/*/tasks.md
   ```

   Отметить `- [x]` только строки `- [ ]`, чей текст целиком выполнен
   этим слиянием (ворота, слияние в целевую ветвь по этому тикету). Сомнение —
   не отмечать, строку в «Решения за пользователем». Файлы сабмодуля
   коммитить в сабмодуле по пути (`git add <файл>`) коммитом
   по-русски с `Co-Authored-By` модели; в репозитории проекта правки
   не коммитить и не отправлять — перечислить в итоге. Готово:
   `grep -c '\- \[ \]'` по файлу уменьшился на число отметок.
5. **Местное.** Worktree с этой ветвью:
   `git -C <сабмодуль> worktree list --porcelain`. Для каждого: дерево
   чистое (`git -C <путь> status --porcelain` пуст) и без процесса
   внутри — `git -C <сабмодуль> worktree remove <путь>`; иначе
   оставить с причиной. Затем `git -C <сабмодуль> branch -d <ветвь>`
   (не `-D`; отказ — оставить с причиной). Готово: `git worktree list`
   и `git branch --list <ветвь>` её не показывают.

## Итог

По `${CLAUDE_PLUGIN_ROOT}/reference/report.md`. Таблица:

| Шаг | Объект | Результат | Проверка |

Затем «Решения за пользователем» (вопросы с вариантами по форме
`report.md`, со строкой «По документам:» — ворота `AskUserQuestion`; шаги 2, 3 и 4 дают для них готовые причины и команды) и
«Что не проверено».

Запрещено: сливать pull request'ы; снимок передачи работы проекта (его
ведёт проектный навык, например `/handoff`); проектные навыки синхронизации
ветвей; коммит и отправка репозитория проекта; `--force`;
удаление защищённых и чужих ветвей; завершение процессов; повтор
после 401/403 от Bitbucket.
