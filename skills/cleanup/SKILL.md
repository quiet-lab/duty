Цель: освободить диск, `/tmp` и деревья, не задев чужого.

Вход: `$ARGUMENTS` — пусто (сухой прогон) или `apply`; после него
сколько угодно `--exclude '<шаблон>'` — glob по имени ветви, ручные
исключения (например, ветви работающих исполнителей).

Правила раскладки, защищённые ветви и признаки чужого —
`${CLAUDE_PLUGIN_ROOT}/reference/layout.md`. Остановленные контейнеры
и деревья стенда — по `${CLAUDE_PROJECT_DIR}/legacy/devlab/AGENTS.md`:
экземпляры стенда снимает только `instances-down` со своими номерами,
деревья ревизий — `instances-prune`.

## Шаги

1. Составить перечень, передав сценарию все `--exclude` из `$ARGUMENTS`:

   ```sh
   python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/cleanup-candidates.py" "${CLAUDE_PROJECT_DIR}" [--exclude '<шаблон>']...
   ```

   Готово, если вывод — таблица с колонками «Вид | Сабмодуль | Родитель |
   Что | Размер | Решение | Команда». Одна строка — один объект: для
   ветви «Что» — имя ветви, для worktree и каталога — путь, для
   контейнера — имя. Строки опознаются по этим полям, номеров нет.
   Сценарий сам пропускает ветви, выписанные в любой worktree (в том
   числе с незакоммиченными изменениями), и ветви, подпавшие под
   `--exclude`: в перечне они с решением «оставлено: …». Сценарий только
   читает (и обновляет ссылки `origin/*` через `git fetch --prune`).
2. Без `apply` — итог по перечню, ничего не удалять.
3. С `apply` — по строкам, где «Решение» начинается со слова «удалить»,
   по одной:
   - перед командой перепроверить условие строки: для worktree —
     `git -C <путь> status --porcelain` пуст; для ветви —
     `git -C <сабмодуль> merge-base --is-ancestor <ветвь> origin/<родитель>`
     успешна (`origin/<родитель>` содержит вершину ветви; слитость в HEAD
     сабмодуля здесь не мерило) и ветвь не выписана ни в одной worktree
     (`git -C <сабмодуль> worktree list --porcelain`); для scratchpad —
     нет процесса с текущим каталогом внутри
     (`ls -l /proc/*/cwd 2>/dev/null | grep -F <путь>` пуст);
   - выполнить команду из колонки «Команда» без изменений; для ветви это
     `git branch -D <ветвь>`, и только сразу после проверки выше;
   - проверить результат: путь исчез (`test ! -e <путь>`), ветвь
     исчезла (`git -C <сабмодуль> rev-parse --verify --quiet <ветвь>`
     не находит), `docker image prune` вывел освобождённое место.
   Строки «оставлено», «решение пользователя» и «сведения» не исполнять.
   Команда `sudo -A -p …` открывает окно ввода пароля; не открылось
   или отказ — строка остаётся «оставлено», обходов нет.
4. После `apply` — повторить шаг 1. Готово, если каждая строка перечня
   либо удалена и проверена командой, либо оставлена с причиной в итоговой
   таблице; повторный прогон показывает только оставленные строки
   с причинами (строка кэша Docker с нулевым освобождаемым объёмом
   не показывается).

## Итог

По `${CLAUDE_PLUGIN_ROOT}/reference/report.md`. Таблица:

| Что | Где | Размер | Удалено / оставлено и почему |

Строки одного вида с одним решением и одним сабмодулем сливаются
в итоговой таблице («36 ветвей QMS, слитых в dev2 — удалены»), в перечне
они остаются отдельными. «Решения за пользователем» — строки «решение
пользователя» с командой. «Что не проверено» — что сценарий
не смог измерить.

Запрещено: завершать процессы (`kill`, `pkill`, `killall`, по образцу);
трогать worktree с грязным деревом и чужие незакоммиченные правки;
удалять ветви `backup/*`, `saved/*`, `dev`, `dev2`, `master`, `new_ocp`,
`dev-local` и ветви коллег; `instances-down all`; действия с root без
`sudo -A -p`; что-либо за пределами перечня.
