Цель: применить одно правило ко всем документам, где оно действует,
и не испортить код, пути, ссылки и идентификаторы.

Вход: `$ARGUMENTS` — правило (замена «A на B» либо описание вроде
«убрать даты поручений»), необязательные `--paths <маски через запятую>`
и `--dry`. С `--dry` правилом может быть и просто слово или образец поиска
(«заказчик»): это образец, замены нет. Правило не разбирается в точный
образец поиска — итог из одной строки с просьбой уточнить.

Корень — `${CLAUDE_PROJECT_DIR}`. Правила языка —
`${CLAUDE_PROJECT_DIR}/docs/russian-prose.md`.

## Шаги

1. **Область.** Без `--paths`: `docs/`, `*.md` в корне, `.claude/rules/`,
   `openspec/`, `AGENTS.md` и `CLAUDE.md` каталогов монорепозитория, кроме
   сабмодулей. Сабмодули (`legacy/*`, `claude-plugins/*` и другие) входят
   только когда `--paths` называет их путь. Не входят: `.git`, `node_modules`,
   архив `openspec/changes/archive/` (история), `docs/decisions/README.md`
   правится лишь вместе с записью. Готово: область названа списком масок.
2. **Перечень.** `grep -rnI -e '<образец>' <область>`; для правила без
   образца сперва составить образец и показать его в итоге. Вывод —
   файл, строка, фрагмент. Готово: число файлов и мест названо.
3. **С `--dry` — остановка** с итогом по перечню, ничего не менять.
4. **Критерии пропуска.** Правило не применяется внутри кода (блоки
   с тремя обратными кавычками и `код` в одинарных), путей и имён файлов,
   ссылок (адрес в скобках), идентификаторов и ключей конфигурации,
   цитат кода и названий тикетов, имён ветвей и записей, кроме случая,
   когда правило прямо о них. Каждый пропуск перечислить в итоге с
   причиной.
5. **Замена.** `sed -i` либо `python3 -I` по точному списку файлов из
   перечня; не по всему дереву. Падежи и согласование («заказчика» →
   «проекта») править осмысленно, не механически; сомнительное место
   не менять, а вынести в «Решения за пользователем».
6. **Вычитка.** Для каждого изменённого места прочесть контекст
   (`git diff -U2`) и проверить: фраза грамотна, смысл сохранён, код и
   ссылки целы. Неудачную замену вернуть. Готово: каждое место отмечено
   «верно» или «возвращено».
7. **Коммит — по репозиториям отдельно.** Монорепозиторий: только
   изменённые файлы по путям, `git add <путь>`, коммит по-русски
   с `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Сабмодуль
   правится, только если `--paths` его назвал, и коммитится в самом
   сабмодуле (`git -C <сабмодуль> add <путь>`), в текущей ветви, без
   push; указатель сабмодуля в монорепозитории не коммитить — назвать
   в «Решения за пользователем». Чужие незакоммиченные правки в тех же
   файлах — файл не коммитить, сообщить. Push не делать.
8. **Особые случаи.** Задет `docs/jenkins-pipelines.md` — в итоге
   напомнить про `just confluence-mirror` (зеркало в Confluence);
   самому не запускать. Задет `docs/` — перед правкой проверить занятость
   ресурса `docs-tree`, если реестр есть (`../ocp-dev-stand/busy/docs-tree.json`
   с живым `pid`); занято — остановка с названием держателя.
