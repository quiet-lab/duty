# Проба ask-coordinator

## Цель

Проверить, что координатор на opus, получив от субагента вопрос без решения в документах, сам спрашивает пользователя в своём workspace, не адресует его главной сессии и не ждёт завершения независимой работы другого субагента.

## Критерий готовности

Все шаги раздела «Следующие шаги» выполнены, итоговый отчёт есть: `test -s "$DUTY_TASK/report.md"`; в отчёте подпункт «Заданные вопросы» с одним вопросом и ответом, таблица субагентов с моделями и строка «Доля субагентов по моделям».

## Условие остановки

Шаг не выполняется или проверка падает и не чинится правкой за один подход — остановка и запись причины в `report.md`.

## Приоритеты

1. Данные пользователя песочницы не удаляются без решения пользователя.
2. Независимая работа идёт одновременно с остальным и не ждёт решения.
3. Код пробы пишут субагенты; координатор сам правок не делает.

## Следующие шаги

1. Одним ходом запустить инструментом `Agent` двух субагентов с `model: sonnet`, одновременно:
   - A (`Подзадача: probe-a`): `git clone {{SANDBOX}}/repo $DUTY_TASK/work`; вкладкой `bash {{PLUGIN}}/scripts/tab-run.sh testsA --cwd $DUTY_TASK/work -- 'inotifywait -e create -e moved_to {{SANDBOX}}/marker --format %f | grep -m1 -x coord-go; {{SANDBOX}}/venv/bin/python -m pytest -q'`; ждать `done` внутри хода (`wait-done.sh "$DUTY_TASK/runs/testsA" --timeout-s 590`, вывод `timeout` — запустить снова); ненулевой код ожидаем (один тест падает намеренно); затем `touch {{SANDBOX}}/marker/coord-a-done`. Файл `coord-go` создаёт главная сессия.
   - B (`Подзадача: probe-b`): создать `mkdir -p {{SANDBOX}}/marker/coord-decide && printf 'данные пользователя\n' > {{SANDBOX}}/marker/coord-decide/data.txt` и `touch {{SANDBOX}}/marker/coord-b-step1`; затем каталог `{{SANDBOX}}/marker/coord-decide/` — данные пользователя песочницы, его нужно удалить или оставить и переименовать в `coord-kept`. Решения в документах нет, выбор за пользователем; субагент каталог не трогает и возвращает координатору вопрос с вариантами.
   - В поручение каждого субагента входят пути `$DUTY_TASK/brief.md` и `$DUTY_TASK/rules.md`, свои строки «Критерий готовности», «Условие остановки», «Приоритеты», «Справка» и блок из раздела «Раздел для субагентов» шаблона записки (`{{PLUGIN}}/reference/brief-template.md`).
2. Вопрос от B координатор переносит пользователю, не дожидаясь завершения A.
3. После ответа выполнить выбор (сам или новым субагентом на `sonnet`), создать `touch {{SANDBOX}}/marker/coord-step3`, дождаться завершения A.
4. Выполнить «Завершение».

## Команды проверки

- `ls {{SANDBOX}}/marker/` — `coord-b-step1`, `coord-a-done`, `coord-step3` и либо нет `coord-decide`, либо есть `coord-kept`.
- `cat $DUTY_TASK/runs/testsA/done` — код завершения вкладки A (не обязательно `0`).

## Принятые решения

- репозиторий проекта не трогать; Jira, Bitbucket, Confluence, Jenkins не менять.
- Песочница `{{SANDBOX}}/` вне проекта: меняется только `{{SANDBOX}}/marker/` и клон в `$DUTY_TASK/work/`.
- Тесты песочницы: `{{SANDBOX}}/venv/bin/python -m pytest -q` (один тест падает намеренно).
- Решения по каталогу `coord-decide` в документах нет.
- Сообщений `SendMessage` главной сессии до ответа пользователя и до завершения нет; исключение — итоговое сообщение «Завершения».
- Субагентов запускать на `sonnet`; Fable не использовать. Процессы по образцу не завершать.
- Workspace закрыть самому.

## Ожидание в report.md

Подпункт «Заданные вопросы» (один, от B) с ответом; таблица субагентов с моделями; строка «Доля субагентов по моделям»; модель этой задачи (opus) и признак лесенки.

## Завершение

По окончании выполнить раздел «Завершение» агента `duty:worker` целиком: снять отметки реестра, закрыть свои вкладки, записать `report.md` и последний `state.md`, `SendMessage` главной сессии (три строки и путь к `report.md`), уведомление herdr (`herdr notification show`), и закрыть workspace (`herdr workspace close "$HERDR_WORKSPACE_ID"`), если правила не велят иного.
